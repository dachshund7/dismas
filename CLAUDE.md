# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Upstream policy on AI contributions

CONTRIBUTING.md says the upstream project (gitlab.gnome.org/World/amberol) **does not accept contributions generated by LLMs**, and names Claude explicitly. This covers code, docs, issues and artwork. Changes made here are for local use only. Don't prepare merge requests, issues or other upstream submissions from AI-generated work.

## Build and run

Amberol is a GTK4/libadwaita music player written in Rust. Build it with Meson, which runs Cargo itself. A plain `cargo build` fails until Meson has generated `src/config.rs`.

```sh
meson setup _build                     # add -Dprofile=development for a debug build with the .Devel app ID
meson compile -C _build                # or: ninja -C _build
meson devenv -C _build ./src/amberol   # run uninstalled
```

- **Generated `config.rs`:** `meson setup` writes `src/config.rs` from `src/config.rs.in` and copies it into the source tree. The file is gitignored. Cargo, rustfmt and clippy all need it to exist.
- **Profiles:** the default profile builds `--release`. Cargo's target dir is `_build/src/`.
- **Runtime dependencies:** gtk4 ≥ 4.19.5, libadwaita ≥ 1.8, GStreamer ≥ 1.20 (incl. plugins-bad), plus `blueprint-compiler` and `msgfmt` (gettext) at build time.
- **Flatpak:** the manifest is `io.bassi.Amberol.json`. CI builds the Devel flatpak.

## Checks

```sh
cargo fmt --all -- --check   # CI runs this; CI creates an empty src/config.rs first
cargo clippy                 # not enforced in CI; existing warnings are present
cargo test                   # the only unit tests are in src/i18n.rs
cargo test <name>            # a single test
build-aux/checks.sh          # fmt + typos (spelling, configured in .typos.toml)
reuse lint                   # CI checks REUSE/SPDX licensing
```

Every source file needs SPDX headers (`SPDX-FileCopyrightText` / `SPDX-License-Identifier`). REUSE.toml covers files that can't carry headers.

## Architecture

### Audio: message passing between threads

`src/audio/mod.rs` has a header comment explaining the design. GStreamer and the controllers can fire from other threads, so nothing touches the UI state directly. Everything goes through async channels:

- `AudioPlayer` (`audio/player.rs`) is the hub. `Application` (`application.rs`) owns it and gives it a sender for `ApplicationAction`s.
- `GstBackend` wraps GstPlay and reports changes over a channel.
- Controllers implement the `Controller` trait (`audio/controller.rs`) and are pushed state changes by the player:
  - `MprisController`: media keys and desktop integration.
  - `InhibitController`: prevents suspend during playback.
- Controllers and the UI ask for things by sending `PlaybackAction`s back to the player.
- `PlayerState` is a GObject whose properties the UI binds to. It is only mutated on the main context.
- `Queue` is the playlist, a `GListModel` of `Track` GObjects. `ShuffleListModel` is a shuffled view over it.
- Covers are deduplicated across tracks of the same album through a global `CoverCache`.
- `WaveformGenerator` builds the seek-bar waveform in a separate GStreamer pipeline.

### UI

- **Composite templates:** each widget is a Rust subclass (`src/*.rs`) bound to a Blueprint template in `src/gtk/*.blp`.
- **Resources:** Meson compiles the `.blp` files to `.ui` and bundles them with CSS and icons through `src/amberol.gresource.xml`. Templates load from `/io/bassi/Amberol/<name>.ui`.
- **Adding a widget:** update the `.blp` list in `src/gtk/meson.build`, the gresource XML and `po/POTFILES.in` together.
- **Window coordination:** `window.rs` is the large coordinator. It installs `win.*` actions, handles drag-and-drop and file loading, runs search/filtering (`search.rs`, `sort.rs`), and binds `PlayerState` to the widgets.
- **Settings:** stored through GSettings (`data/io.bassi.Amberol.gschema.xml`).
- **Saved playlist:** kept in the user cache dir (`utils.rs`) so "Restore Playlist" can reload it.

### Translations

- UI strings use gettext helpers from `src/i18n.rs` in Rust, and `_()` / `C_()` in Blueprint.
- `po/*.po` files are maintained by GNOME translators (Damned Lies), so don't edit them by hand. New translatable files go in `po/POTFILES.in`.

## Conventions

- Commit messages: a one-sentence summary line of at most 72 chars, capitalized, with no trailing period. Then a blank line and a prose body explaining *why*. Use `Closes #N` / `Fixes #N` for issues.
- The UI calls audio files "tracks" (not "songs"). Keep the freedesktop icon name `media-playlist-repeat-song-symbolic` as is.
